# Цифровой двойник завода АЛЛЮР

> Подробно о системе, модулях, формулах и ролях — **[docs/SYSTEM.md](docs/SYSTEM.md)**.

MVP для кейса №2 Qostanai Industry Hackathon (Demo Day — 16.10.2026).
Показывает состояние завода, выявляет проблемы, прогнозирует риски и предлагает управленческие действия:
**MONITOR → ANALYZE → PREDICT → RECOMMEND**.

## Запуск

```bash
make up        # собрать и запустить в Docker → http://localhost:8080
make down      # остановить
make logs      # логи
make help      # все команды
```

Нужны только Docker и Docker Compose. Ключ Claude API необязателен: без него AI-рекомендации собираются по шаблонным правилам, и демо работает офлайн.
Чтобы включить Claude, впишите `ANTHROPIC_API_KEY` в `.env` (создаётся автоматически из `.env.example`) и выполните `make restart`.
Проверить режим можно командой `make health`: `"llm": true`.

### Разработка без Docker

```bash
make install   # venv для backend + npm ci
make dev       # API :8000 + Vite :5173 (прокси /api)
make test      # pytest (50 тестов) + typecheck фронтенда
make e2e       # smoke демо-сценария (нужен pip install playwright)
make static BASE_PATH=/<проект>/   # статическая сборка без сервера → public/
```

### Статический хостинг (GitHub Pages)

Данные кейса фиксированные, поэтому сайт может работать без сервера. `python -m app.export_static` вызывает настоящие маршруты API и выгружает ответы в JSON. Фронт со сборкой `VITE_STATIC=1` читает эти файлы, а калькулятор эффекта считает в браузере: формулы сверяются с Python тестом.

### Vercel (из приватного репозитория, бесплатно)

`vercel.json` и `scripts/vercel-build.sh` уже настроены: Vercel сам собирает статику при каждом пуше в `main`.

1. https://vercel.com → **Add New… → Project** → импортировать `overdobro/allur-digital-twin`. Root Directory оставить корнем репозитория, остальные настройки подтянутся из `vercel.json`.
2. Необязательно: **Settings → Environment Variables → `ANTHROPIC_API_KEY`**, затем Redeploy. Тогда рекомендации Claude сгенерируются при сборке, а сам ключ в сайт не попадёт.

Сборка: Python 3.12 выгружает ответы API в JSON, затем фронтенд собирается в статическом режиме. В Amazon Linux 2023, на котором работает Vercel, `python3` — это 3.9, поэтому скрипт сам выбирает версию 3.10+. Прямые ссылки (`/whatif`, `/sections/painting`) отдаются через rewrite на `index.html`.

### CI (GitHub Actions)

- `.github/workflows/ci.yml` — на каждый пуш в `main` и pull request: тесты бэкенда; экспорт → `tsc` → `vitest` → сборка фронтенда (обычная и статическая); сборка Docker-образов.
- `.github/workflows/pages.yml` — публикация статической версии на GitHub Pages, запускается вручную: Actions → Pages → Run workflow. Перед первым запуском включите Settings → Pages → Source: GitHub Actions. Для приватного репозитория Pages доступны только на платных тарифах GitHub. Если задать секрет `ANTHROPIC_API_KEY`, рекомендации Claude сгенерируются при сборке, а сам ключ в сайт не попадёт.

## Что внутри

- **3D-цех** на обзоре:
  - оборудование: роботы Сварки, камера Окраски, портал Сборки, ОТК, склады;
  - кузова движутся с темпом участков, перед узким местом образуется очередь, брак съезжает в контейнер;
  - клик по подписи участка открывает панель и подводит камеру.
  
  Переключатель **3D / 2D**. Без WebGL, на телефоне или при выключенных анимациях показывается 2D. На слабой графике качество снижается автоматически.
- **Что если** (`/whatif`):
  - вкладка «Два будущих» — без действий против рекомендаций AI;
  - вкладка «Песочница» — ползунки темпа и брака, смены, дни.
  
  Модель: устойчивый выпуск = min по участкам (темп × (1 − брак)).

## Сценарий демо (2–3 мин)

1. **Обзор завода**: живой конвейер. Кузова едут с темпом участков, перед Сваркой образуется очередь, на Окраске бракованные кузова уходят с линии. «▶ Воспроизвести смены» проигрывает события 01.10 → 02.10, и они всплывают над участками.
2. **KPI**: брак 3,2% (Окраска 5,2% — в 2,6 раза выше нормы), расчётный OEE (худшая линия — Сварка, 81%), прогноз месяца 5 280 из 5 500.
3. **Клик по «Окраске»** (открывается боковая панель): брак 3,5% → 5,2%, инцидент Камеры-02 (замена фильтра, 40 мин).
4. **Простои**: самый длительный простой — Конвейер-03, 55 мин (92% суточной нормы).
5. **AI Risk**: анимированный анализ MONITOR → ANALYZE → PREDICT → RECOMMEND. Окраска — проблема уже случилась. Сварка — назревает: OEE 94,2% → 81,0%, падают все составляющие. Узкое место сместилось с Окраски на Сварку.
6. **Рекомендации**: конкретные действия до следующей смены (Камера-02, датчики ABB-01, ABB-04 после ТО).
7. **Руководителю**: 3 строки приоритетов, «AI рекомендации», план 5 500 недостижим даже при 100% сменного плана (нужно ≈125 авто/смену), эффект: +118 кузовов/мес без переделки при браке Окраски 2%.
8. Финальная фраза: «Цифровой двойник не просто показывает проблему — он помогает принять решение до того, как проблема приведёт к потерям».

## Архитектура

```
docs/ (кейс, тестовые данные)
   │  перенесены 1:1
   ▼
backend/app/data/seed.json ──► repository ──► services/
                                               ├─ kpi.py     расчётный OEE, статусы по порогам
                                               ├─ twin.py    модель завода: участки, оборудование
                                               ├─ risk.py    Risk Engine + Bottleneck Detector
                                               ├─ advisor.py Claude API (structured output) ↔ fallback на правила
                                               ├─ effect.py  прогноз месяца, бизнес-эффект
                                               └─ replay.py  хронология событий
                                               ▼
                                   FastAPI /api/* ──► nginx ──► React (Vite, Tailwind, ECharts)
```

- **Честность данных.** Всё вычисленное помечено «расчётный». Допущения A1–A8 описаны на странице «Допущения и методика» и отдаются в `/api/meta`.
- **Статусы** считаются только по порогам из `backend/app/config.py`, вручную не проставляются.
- **ИИ.** Risk Engine — прозрачная факторная модель: отклонение от норматива плюс тренд, у каждого фактора есть доказательство из данных. Claude получает уже посчитанные факты и только формулирует рекомендации. Числа он не выдумывает: это запрещено промптом, а ответ проверяется по JSON-схеме. По 2 дням данных точность модели не заявляется.

## API

| Метод | Назначение |
|---|---|
| `GET /api/overview?date=` | KPI + карта завода |
| `GET /api/sections/{id}?date=` | детализация участка |
| `GET /api/production`, `/quality`, `/downtime` | разделы |
| `GET /api/risk` | риски, факторы, узкое место |
| `GET /api/advice[?refresh=true]` | AI-рекомендации (Claude / правила) |
| `GET /api/forecast`, `/api/effect` | прогноз месяца, бизнес-эффект |
| `GET /api/replay` | хронология для воспроизведения |
| `python -m app.export_static <dir>` | выгрузка всех ответов в JSON для статики |
| `GET /api/meta` | даты, нормативы, допущения, пороги |
