# Цифровой двойник завода АЛЛЮР — как устроена система

> АО «Группа компаний АЛЛЮР», Костанай · цифровой двойник производственной линии
>
> Документ для всех: первая часть — простыми словами (что это и зачем), вторая — модули по очереди, третья — формулы и техническое устройство.

---

## 1. Коротко

**Цифровой двойник** — это виртуальная копия производственной линии завода, которая живёт на реальных данных смен.
Линия: **Склад комплектующих → Сварка → Окраска → Сборка → Контроль качества → Склад готовой продукции**.

Система делает три вещи:

| | Что делает | Пример из тестовых данных |
|---|---|---|
| 👁 **Видит** | Показывает состояние каждого участка и оборудования против нормативов | Брак Окраски 5,2% при норме ≤ 2% — красный статус |
| 🧠 **Объясняет** | Находит причины отклонений, оценивает риск, предлагает действия на смену | OEE Сварки упал 94,2% → 81,0%, узкое место смещается на Сварку |
| 🧪 **Проверяет заранее** | Проигрывает решение до внедрения и считает, сколько автомобилей оно даст | Третий робот на посту геометрии: 4 752 → 4 839 авто/мес |

Зачем это заводу: руководитель узнаёт о проблеме **до** того, как она привела к потерям, и проверяет решение **до** того, как потратил деньги.
Плюс завод получает поток идей от сотрудников и студентов — с предварительной оценкой и проверкой на модели.

## 2. Главный принцип: данные → расчёт → AI → решение человека

```
 📊 Данные смен            🧮 Расчёт (код)              ✦ AI (Claude)                 ✅ Решение
 выпуск, план, брак,  ──►  KPI, OEE, статусы по   ──►  объясняет отклонения,   ──►  принимает человек:
 простои, события          порогам, узкое место,       формулирует риски и          руководитель — по заводу,
 оборудования              прогноз, «что если»         рекомендации                 эксперт — по гранту
```

Три правила, на которых держится доверие к системе:

1. **Числа считает код, а не AI.** Claude получает уже посчитанные факты и только формулирует выводы. Придумывать числа ему запрещено, ответ проверяется по JSON-схеме.
2. **Всё, что посчитано по допущению, помечено «расчётный».** Допущения A1–A9 открыты в разделе «Допущения и методика» (список — в §6).
3. **Без ключа Claude система работает так же.** Те же выводы собираются правилами; на экране видно, кто ответил: «Claude» или «правила · без LLM».

## 3. Роли и вход

При открытии сайта — экран **«Как вы хотите войти?»**:

| Роль | Как войти | Что видит |
|---|---|---|
| 👔 **Руководитель** | логин и пароль (демо: `manager` / `allur2026`) | Весь завод: обзор, линии, план, качество, простои, AI Risk, «Что если», 3D-редактор, отбор идей |
| 🦺 **Сотрудник** | выбор демо-аккаунта `emp_01…emp_06` | Своя смена, выполненные работы, сообщения о проблемах, свои идеи |
| 🎓 **Обучающийся** | выбор демо-аккаунта `student_01…student_08` | Профиль, свои идеи с AI-оценкой, проверка в 3D, рейтинг и грант |

Права проверяются на сервере: сотрудник не увидит чужие данные, обучающийся не поставит оценку эксперта, а подделать роль в cookie нельзя — она подписана и сверяется с базой.

## 4. Модули

Для каждого модуля: **зачем**, **что на экране**, **как считается**.

### 4.1. Руководитель

#### Обзор завода (`/`)
- **Зачем:** за 10 секунд понять, что происходит на заводе.
- **На экране:**
  - 4 KPI: OEE, брак, простой оборудования, выпуск — с цветом статуса и изменением ко вчера;
  - **3D-цех**: кузова едут по линии с темпом участков, меняются по ходу (металл → грунт → цвет → колёса), перед узким местом копится очередь, брак уходит с линии;
  - клик по участку — боковая панель с деталями и оборудованием;
  - «▶ Воспроизвести смены» — хронология событий 01.10 → 02.10;
  - панель «Требует внимания»: риски и открытые сообщения сотрудников.
- **Как считается:** статусы — только по порогам (§5.2); выпуск завода — выход Сборки (A3).
- Без WebGL или на телефоне показывается 2D-схема; на слабой графике качество 3D снижается автоматически.

#### Линии (`/production`)
- Карточки производственных линий: план, факт, выполнение, OEE, брак, оборудование; связь «участок → линия → план → 3D».

#### План (`/plan`)
- **Зачем:** ответить на вопрос «выполним ли мы план месяца».
- **На экране:** план по моделям (Onix 2 500, Cobalt 1 800, JAC J7 500 = 4 800 авто/мес) на смену, день и месяц; план-факт; прогноз; зоны риска невыполнения.
- **Вывод по данным:** прогноз 5 280 авто/мес → план по моделям выполним, а цель 5 500 — нет (−220; нужно ≈125 авто/смену).
- Факт по моделям в данных нет — он **расчётный** (A9).

#### Качество (`/quality`) и Простои (`/downtime`)
- Брак по участкам и динамика; журнал простоев оборудования с нормой 60 мин/сутки.
- На странице простоев — **«Сообщения с участков»**: что сообщили сотрудники; руководитель принимает в работу или закрывает.

#### AI Risk (`/ai`)
- **Зачем:** увидеть не только «что уже плохо», но и «что назревает».
- **На экране:** цепочка MONITOR → ANALYZE → PREDICT → RECOMMEND; риск по каждому участку с факторами и доказательствами из данных; **Bottleneck Detector** — где теряется больше всего годных автомобилей.
- **Вывод по данным:** Окраска — проблема уже случилась (брак 5,2%); Сварка — назревает (OEE 94,2% → 81,0%, падают все три составляющие).

#### Что если (`/whatif`)
- **«Два будущих»:** без действий — 4 752 авто/мес; с рекомендациями AI — 5 002.
- **«Песочница»:** ползунки темпа и брака по участкам, число смен и рабочих дней.
- Модель: **устойчивый выпуск = минимум по участкам (темп × (1 − брак))** — линия идёт со скоростью самого медленного участка.

#### Руководителю (`/executive`)
- Приоритеты на следующую смену и конкретные действия (проверить Камеру-02, откалибровать датчики ABB-01, проверить ABB-04 после ТО).
- Калькулятор эффекта: +118 кузовов/мес без переделки при снижении брака Окраски до 2%.

#### 3D-редактор (`/editor`)
- **Зачем:** проверить изменение расстановки оборудования **до** внедрения.
- **Что можно:** выбрать объект, перетащить, повернуть (R), убрать (Del), добавить из каталога (робот, датчик, буфер, рабочий пост, пост машинного зрения, компрессорная, андон, кондуктор).
- **Что проверяет:**
  1. **Столкновения** — габариты объектов в плане с учётом поворота: с другим оборудованием, с несущими конструкциями (ванны КТЛ, печь, камера ЛКП, стойки конвейера, стенды), с коридором движения кузова, с границей цеха. Конфликтный объект подсвечивается красным.
  2. **Свободное место** на затронутом участке: было → стало, %.
  3. **Было → изменение → стало:** устойчивый выпуск и узкое место по модели «Что если».
  4. **Последствия** списком, включая честное «в модели выпуск не меняется» там, где эффекта не посчитать.
- **AI-оценка изменения:** смысл, риски, следующий шаг (пилот / исправить расстановку / эксперт / не внедрять). Если есть конфликт габаритов — всегда «исправить расстановку», это не на усмотрение модели.
- **Сценарии:** сохранить и загрузить вариант расстановки.
- Влияние оборудования на темп и брак — **сценарные допущения** (§5.5), они раскрываются под результатом.

#### Идеи и грант (`/ideas`)
- Все идеи сотрудников и обучающихся: фильтр по статусу, AI-анализ, итог проверки в 3D.
- **Решение эксперта:** оценка 1–10, комментарий, статус: шорт-лист → финалист → победитель гранта (победителем может стать только финалист с оценкой эксперта) или «отклонить».
- Надпись на экране: **«AI не принимает решение о гранте»**.

### 4.4. Режим презентации

## 5. Как считается (формулы и правила)

### 5.1. KPI

| Показатель | Формула |
|---|---|
| **OEE** (расчётный, A2) | Доступность × Производительность × Качество; Доступность = время работы / 8 ч; Производительность = факт / план (не выше 100%); Качество = 1 − брак / выпуск |
| **Выпуск завода** (A3) | выход последнего участка (Сборки), а не сумма по линиям |
| **Прогноз месяца** (A4) | средний выпуск Сборки за смену × 2 смены × рабочие дни (22) |
| **Простой** (A5) | норма 60 мин/сутки на единицу оборудования; плановое ТО не считается аварийным |

### 5.2. Статусы (только по порогам, вручную не ставятся)

| Метрика | Норма 🟢 | Внимание 🟡 | Критично 🔴 |
|---|---|---|---|
| Брак | ≤ 2% | ≤ 3% | > 3% |
| OEE | ≥ 85% | ≥ 75% | < 75% |
| Выполнение плана | ≥ 98% | ≥ 95% | < 95% |
| Аварийный простой единицы за сутки | < 45 мин | 45–60 мин | > 60 мин |

Пороги лежат в одном месте — `backend/app/config.py`.

### 5.3. Риск и узкое место

- **Индекс риска участка** = сумма вкладов факторов: отклонение от норматива + тренд между сменами. У каждого фактора есть доказательство из данных. Обучаемой модели нет: двух дней данных для неё мало, и точность не заявляется.
- **Узкое место** = участок с наибольшими потерями годных единиц к плану (недовыпуск + брак).
- **Стадия:** «уже случилось» (показатель за пределами нормы) или «назревает» (в норме, но быстро ухудшается).

### 5.4. Модель «Что если»

Устойчивый выпуск за смену = **min по участкам (темп × (1 − брак))** → × смены × рабочие дни. Узкое место — участок, на котором достигается минимум.

### 5.5. Допущения 3D-редактора (влияние одной единицы оборудования)

| Объект | Участок | Влияние |
|---|---|---|
| Робот | Сварка / Окраска / Сборка | ±4 / ±2 / ±2 авто/смену |
| Кондуктор | Сварка | ±3 авто/смену |
| Рабочий пост | Сварка / Окраска / Сборка | ±2 / ±1 / ±2 авто/смену |
| Датчик | Окраска (у Камеры-02) | брак −1 п.п. |
| Датчик | Сборка (вибрация Конвейера-03) / Сварка | +1 авто/смену |
| Буфер, пост контроля, компрессорная, андон | — | в модели выпуск не меняют (честно пишется, почему) |

Перемещение внутри участка не меняет число единиц оборудования — выпуск в модели не меняется, эффект (длина магистралей, проходы, логистика) оценивает технолог.

### 5.6. Оценка идей

- **Балл AI (0–100)** считает код, а не модель: 90 баллов = эффект 50% + реалистичность 30% + простота внедрения 20%; ещё 10 баллов — **конкретность** (названо оборудование из тестовых данных + измеримый механизм).
- **Высокий эффект** ставится, только если идея бьёт в реальную проблему участка по данным (брак Окраски, темп Сварки, простои Конвейера-03).
- **Итоговый балл в рейтинге:** без оценки эксперта — балл AI; с оценкой — **40% AI + 60% эксперт** (1–10 → 0–100).
- **Сценарий для 3D:** AI (или правила) предлагает действие — добавить / переместить / убрать объект на участке. Место на модели подбирается автоматически: первое свободное без пересечений, ближе к естественной позиции (робот — у поста геометрии, датчик — у Камеры-02).

## 7. AI в системе

| Где | Что делает Claude | Чего не делает | Без ключа |
|---|---|---|---|
| Рекомендации руководителю | «Что случилось → почему → риск → что сделать» по посчитанным факторам | Не считает и не придумывает числа | Шаблонные правила |
| Оценка идеи | Участок, реалистичность, эффект, сложность, риски, что проверить, сценарий для 3D | Не ставит балл (его считает код) и не решает о гранте | Правила по ключевым словам и данным участка |
| Оценка изменения в редакторе | Смысл, риски, следующий шаг | Не отменяет конфликт габаритов | Правила |

Модель: `claude-opus-5-5`, структурированный ответ по JSON-схеме. Ключ хранится только на сервере и в браузер не попадает.


### 7.1. Режим без Claude

Без ключа (или при сбое сети, тайм-ауте, ответе не по схеме) отвечают правила. Ничего не выключается, числа те же — их считает код. На экране метка «правила · без LLM».

**Как правила разбирают идею:**

1. **Участок** — по числу совпадений ключевых слов (окраска, камера, фильтр…; сварка, кондуктор, ABB…); названное оборудование из данных (ABB-01, Камера-02, Конвейер-03) весит вдвое больше.
2. **Тип идеи** — изменение оборудования, обслуживание, организационная мера, развитие персонала, цифровое решение, логистика, безопасность, увеличение рабочего времени. От типа зависят механизм эффекта, типичные риски и что проверять.
3. **Связь с проблемой участка по данным** — бьёт ли идея в главную проблему (брак Окраски 5,2%, OEE Сварки 81%, простой Конвейера-03 55 мин). Только тогда эффект «высокий»; цифровые решения и обучение действуют косвенно — эффект «средний».
4. **Сценарий для 3D** — объект, упомянутый первым, и действие («перенести/убрать X» — только если X стоит сразу после глагола).

**Как выглядят ответы (реальные, режим правил):**

> **Идея «Датчик перепада давления на фильтрах Камеры-02»** · балл 100
> Это изменение оборудования на участке «Окраска». Идея бьёт в главную проблему участка: брак 5,2% при норме ≤2% (в 2,6 раза выше). Меняет расстановку или состав оборудования — эффект на выпуск можно проверить на 3D-модели до покупки. Предлагаемое изменение для 3D: добавить «датчик».
> Реалистичность — высокая · Эффект — высокий · Сложность — низкая
> Риски: калибровка и ложные срабатывания; интеграция данных с цифровым двойником; ограниченные данные: 2 дня наблюдений
> Что проверить: брак окраски до и после (сейчас 5,2% при норме ≤2%); простои Камеры-02 · Следующий шаг: проверка на 3D-модели

> **Идея «Геймификация предложений»** · балл 36
> Это мера по развитию персонала, но участок не определён — уточните, на каком участке её внедрять, тогда оценка будет точнее. Работает через навыки и вовлечённость людей — эффект проявляется не сразу.
> Риски: нужно время на обучение вне смены; эффект трудно измерить быстро; эффект не подтверждён тестовыми данными · Следующий шаг: экспертная оценка

> **Изменение в редакторе: добавлен робот на Сварку**
> Добавлен: Робот (6 осей). Устойчивый выпуск 4752 → 4839 авто/мес (+87), узкое место смещается с «Сварка» на «Окраска».
> Риски: узкое место смещается — теперь выпуск ограничивает «Окраска»; робот: наладка программы и ограждение ячейки, простой участка на время монтажа; влияние на темп — допущение модели
> Следующий шаг: **пилот на одной смене**. Проверить на одной смене: замерить темп участка и сравнить с моделью (+87 авто/мес). После изменения выпуск ограничивает «Окраска» — следующая мера должна быть там.
> *Если робот задевает ABB-04:* следующий шаг — **исправить расстановку**: «Сначала устранить пересечения (1): переместить объект на свободное место участка и пересчитать».

> **Рекомендация руководителю: Окраска**
> Что случилось: брак 5,2% при норме ≤2% (в 2,6 раза выше). Почему: брак растёт 3,5% → 5,2%; простой Камеры-02 — замена фильтра, 40 мин (01.10); гипотеза для проверки (A7). Риск: брак уже превышает норму и растёт — потери годных автомобилей и переделки. Что сделать: проверить Камеру-02 после замены фильтра — посадку и герметичность фильтра, перепад давления, расход воздуха; до начала смены ввести усиленный выборочный контроль.

**Как показать работу без Claude (2–3 мин):**

1. «▶ Презентация» → слайд «Как отвечает AI»: на нём видно, что сейчас отвечают правила. Сказать прямо: «Ключ не нужен — числа считает код, правила формулируют вывод».
2. Шаг «Ответ AI: рекомендация по участку» — что случилось → почему → риск → что сделать, каждое утверждение со ссылкой на данные.
3. Шаг «Ответ AI: оценка изменения» — робот на Сварке: +87 авто/мес, смещение узкого места, риск монтажа, шаг «пилот».
4. Шаг «Ответ AI: анализ идеи» — тип идеи, связь с проблемой участка, балл по формуле.
5. Вживую: войти студентом, подать идею своими словами — ответ приходит мгновенно. Показать слабую идею («полностью автоматическая сборка без людей») — правила честно ставят низкую реалистичность и советуют сузить.
6. Финал: «С ключом Claude текст становится свободнее и понимает любые формулировки; без ключа система не ломается и не врёт цифрами».

Ограничение правил: они понимают знакомые слова. Идея, сформулированная необычно, может получить «участок не определён» — тогда автор выбирает участок в форме, и оценка уточняется.

## 9. Техническое устройство


### 9.4. Безопасность

- Пароли — PBKDF2-SHA256; сессия — подписанная cookie (HMAC), роль каждый раз сверяется с базой.
- Права проверяются на сервере для каждого запроса.
- Ключ Claude, пароль руководителя и секрет подписи — переменные окружения (`ANTHROPIC_API_KEY`, `MANAGER_PASSWORD`, `SECRET_KEY`), в репозиторий не попадают.

### 9.5. Запуск и проверка

```bash
make up      # Docker → http://localhost:8080
make dev     # разработка: API :8000 + Vite :5173
make test    # pytest + typecheck
make e2e     # сквозной сценарий в браузере
```

Тесты: pytest (72) — расчёты, роли, идеи, сценарии; vitest (28) — модель «Что если», геометрия и последствия редактора, идея → 3D; e2e — вход, все разделы, презентация, консоль без ошибок.
